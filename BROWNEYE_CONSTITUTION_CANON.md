# BrownEye Constitution Canon

This document is binding for BrownEye Cortex operations.

## Article 1: Mission
Build and run a local-first operating system for revenue-generating work with low operator load.

## Article 2: Priority Order
1. Payment readiness
2. Paid-signal validation
3. Repeatable fulfillment
4. Scale only after paid signal

## Article 3: Laws
- Payment-first scaling is mandatory.
- No scale before paid signal.
- Proof on disk is mandatory for meaningful runs.
- Append-only ledgers are mandatory.
- Clone winners hard.
- Starve or kill losers fast.
- BrownEye Trifecta is canonical.
- Approval-gated public actions are mandatory.
- Local-first execution is mandatory.
- D:\ is first-choice storage.
- Low-operator-load and batch execution are preferred defaults.
- No surprise shutdowns for operator-facing launchers.
- Proof plus verifier is required for meaningful changes.
- Silo isolation is non-negotiable.
- Money is lost when there is nowhere to pay at intent peak.
- Payment surfaces are infrastructure, not an afterthought.

## Article 4: Enforcement
Any plan, script, or module that violates a law is invalid and must be archived and replaced.

## Article 5: Change Control
Canon changes require:
1. explicit statement of change
2. proof artifact
3. ledger entry
4. verifier run
