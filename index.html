BROWNEYE CORTEX · CASH MACHINE LIBRARY

Closed-Loop Transaction Modules for Two-Computer Automation

The following system design delivers one-off, low-friction revenue modules built for the Furnace (always-on) and Cortex (burst GPU) split. Each module is a repeatable "SimCity building" that captures cash where money already flows, produces proof logs, and resets for reuse without subscriptions or audience-building.

Output 2: Generic Drop-In Building Blueprint

Shared Architecture Stencil

  • Common Folder Layout: /modules/<module-name>/manifest.json, /jobs/incoming, /jobs/processing, /jobs/delivered, /proofs, /assets/templates.
  • Job Queue Schema: job_id, buyer_id, module, input_refs, price_tier, status, timestamps, retries, checksum.
  • Logging + Proof: immutable JSON log + hash, delivery link, payment receipt, QA summary.

Payment Trigger Pattern

  • Flow: one-off payment → unlock job → validate input → run pipeline → deliver → log proof → close job.
  • Access: temporary upload portal tied to payment intent.
  • Refund Rule: auto-refund if SLA breached or validation fails.

Latency Model Pattern

  • Free Delay vs Paid Instant: optional delay queue (24-48h) vs paid priority processing within 2-4 hours.
  • Queue Control: Furnace enforces FIFO with priority flag.

Health Checks + Watchdogs

  • Furnace: uptime pings, queue depth alerts, failure-rate threshold, retry backoffs.
  • Cortex: burst executor, GPU availability check, QA sampling after each batch.
